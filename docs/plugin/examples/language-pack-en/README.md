# 예제: 언어팩 템플릿 (`contributes.translations` — 선언형 전용)

영어는 이제 **번들 언어팩**으로 앱에 함께 실린다(`src/plugin/builtin/language-packs/language-pack-en/`, 이슈 #30) — 이 폴더는 더는 그 원천이 아니라
**언어팩을 어떻게 만드는지 보여 주는 축약 템플릿**이다. 크기를 작게 유지하려고 `entries`에는
대표 키 5개만(플레이스홀더 없음·하나·여러 개 각각 예시) 담았다 — 실전 언어팩은
`src/i18n/ko.json`이 가진 키 전부를 채워야 한다("나만의 언어팩 만들기" 참고).

**이 폴더는 문서 전용 템플릿이다** — 어떤 테스트도 픽스처로 쓰지 않는다(e2e는 자기 픽스처를
따로 갖는다). 유일한 역할은 "언어팩 매니페스트가 어떻게 생겼는가"를 사람과 AI에게 보여
주는 것이다.

언어팩에는 **런타임 등록 API가 없다.** 매니페스트 `contributes.translations` 하나가 계약
전부이고, 그래서 이 저장소에서 유일한 "선언형 전용(main.js 없음)" 예제이기도 하다.

## 이 예제가 보여 주는 것

- **언어팩은 능력(capability)이다.** `kind: "capability"` + `permissions: ["i18n"]`가 있어야
  수집된다 — 테마·배경·폰트·창 컨트롤과 같은 게이트다. 다만 **어긋나도 오류가 뜨지 않는다**:
  이 선언을 읽는 것은 브리지 게이트키퍼가 아니라 코어(Rust)이고, 자격이 없는 플러그인은
  그냥 수집 대상에서 빠진다. 그래서 아래 5번의 `lint`가 실질적인 안전망이다.
- **main.js는 공백 하나(개행)뿐이다.** 등록할 게 매니페스트 밖에 없으면 JS를 실행할 이유가
  없다. `entry` 필드 자체는 필수라 파일은 있어야 하지만(빈 문자열이면 스캔이 통째로 버린다 —
  파일을 읽다 실패한 것과 구분이 안 되기 때문), **내용이 공백뿐**이면 호스트는 이 플러그인의
  샌드박스(iframe)를 아예 띄우지 않는다(`docs/plugin/manifest.schema.json`의 `contributes`
  설명, `src/plugin/central-host.ts`의 `code.trim() === ""` 분기). 주석만 있는 파일은
  "공백뿐"이 아니므로 이 최적화를 못 받는다 — 트리밍만 보는 얕은 판정이라 그렇다.
- **호스트도 샌드박스도 이 데이터를 만지지 않는다.** 코어(Rust
  `src-tauri/src/plugin_i18n.rs`)가 설치 매니페스트를 직접 스캔해 각 창에 공급한다 — 그래서
  창이 첫 화면을 그리기 **전에** 이미 그 언어로 뜬다(예전에는 호스트를 왕복하느라 한국어로
  한 번 그린 뒤 리로드해야 했다). 항목 형식(`locale`·`label`·`entries`·256KB 상한)의 정본은
  그 파일의 `parse_translation`이다.
- **콘텐츠 검증은 수집이 아니라 소비 시점(각 창)에** 일어난다. `entries`의 각 키는 그 창의
  ko 사전과 대조돼, (1) ko에 없는 키는 조용히 버려지고 (2) `{플레이스홀더}` 집합이 ko 문장과
  다른 키만 그 키 하나만 거부된다(`src/i18n/validate.ts`) — 언어팩 하나의 실수가 로드
  전체를 막지 않는다.
- **`ko`와 번들 팩이 등록한 코드(`en`)는 서드파티 언어팩으로 등록할 수 없다.** 이 예제의
  `locale`도 `"en"`이지만, 실제 앱에 설치해 활성화해도 `src/i18n/store.ts`의
  `registerLocale`이 조용히 무시한다(ko는 기준 언어라 처음부터, en은 번들 팩이 등록되는
  순간 보호 집합에 든다 — 서드파티가 앱 내장 번역을 덮어쓸 수 없다). 이 폴더는 순수하게
  **구조를 보여 주는 용도**다.

## 나만의 언어팩 만들기

1. 이 폴더를 통째로 복사하고 `manifest.json`의 `id`·`name`을 바꾼다(폴더 이름도 `id`와 같게).
   `locale`도 목표 언어(en 이외)로 바꾼다 — 예: 프랑스어라면 `"fr"`.
2. `src/i18n/ko.json`을 기준으로 `entries`를 채운다 — **키는 그대로**, 값만 옮긴다. 이 예제의
   5개 키는 시작점일 뿐, 실전 언어팩은 ko.json이 가진 키 전부를 채워야 커버리지가 100%가
   된다(완성형 예: `src/plugin/builtin/language-packs/language-pack-en/manifest.json` — 이 폴더와 **같은 형태**로 실전 크기를 채운 것이다).
   - `{이름}` 형태의 플레이스홀더는 이름까지 **정확히** 같아야 한다(순서는 상관없다). 하나라도
     빠지거나 오타가 나면 그 키만 등록에서 빠지고 나머지는 살아남는다.
   - ko에 없는 키를 추가해도 무시된다 — 옮길 대상은 ko가 가진 키 전부다.
   - 조사 병기(`…을(를)`)처럼 한국어 전용 표기는 대상 언어의 자연스러운 어순으로 풀어 쓴다.
3. `locale`은 BCP47 소문자 단순형(`en`·`en-us`·`pt-br`)만 허용된다. `label`은 언어 드롭다운에
   보일 표시 이름이다(빈 문자열 불가).
4. 등록할 JS가 정말 없다면 `entry`가 가리키는 파일을 **공백(개행 하나)만으로** 둔다 — 그러면
   샌드박스가 뜨지 않는다. 초기화 로그 같은 걸 남기고 싶다면 `memo.runtime.ready()`를 부르는
   최소 스크립트를 써도 된다(그 경우엔 당연히 샌드박스가 뜬다).
5. 저장소 루트에서 `npm run plugin -- lint <폴더>`로 검사한다 — `entries`의 항목별 유효성은
   런타임 소비 시점 검증(ko 대조)이라 lint가 대신 잡지 못한다. 실제로 화면이 그 언어로
   뜨는지는 앱을 켜고 「설정 › 외형 › 테마」의 언어 드롭다운에서 바꿔 확인하는 것이 정본이다.

`contributes.translations`, 사람이 읽는 설명은 [`../../authoring.md`](../../authoring.md)의
「언어팩」 절을 참고. UI 문자열 규약(키 형식·조사 병기·폴백 체인)은
