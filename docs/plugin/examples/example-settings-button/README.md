# 예제: 설정 화면 액션 버튼

설정 › 도구 › 이 플러그인 페이지에 **「지금 메모 확인」 버튼**을 놓습니다. 누르면 확인을 한 번 받고, 지금 메모의 경로를 토스트로 알립니다.

## 설정

| 키         | 뜻                                                           |
| ---------- | ------------------------------------------------------------ |
| `whereAmI` | 값이 없는 **액션 버튼**(`type: "button"`) — 누르는 것이 전부 |

## 무엇을 보여주나

### 1. 매니페스트 한 필드 + 명령 하나

```jsonc
// manifest.json
{
  "key": "whereAmI",
  "type": "button",
  "label": "지금 메모 확인",
  "command": "where-am-i",
  "confirm": "지금 메모의 경로를 확인할까요?",
}
```

```js
// main.js
memo.commands.register({ id: "where-am-i", title: "지금 메모 확인", run: function (memo) { … } });
```

`command`와 `id`가 **글자 그대로 같아야** 한다. 버튼 전용 콜백 API는 없다 — 설정 버튼과 단축키가 같은 명령을 실행하므로 핸들러·권한 게이트·진단이 한 벌이다. 어긋나면 버튼은 뜨는데 눌러도 아무 일이 없고, `npm run plugin -- lint <폴더>`가 그 어긋남을 `UNKNOWN_COMMAND_ID`로 잡는다.

`button`은 **값을 저장하지 않는 유일한 필드 타입**이다. `memo.settings.get({ key: "whereAmI" })`로 읽을 값이 없다(상태 파일에도 그 키가 생기지 않는다).

### 2. 설정 창에는 메모가 없다

```js
memo.notes.current().then(function (note) {
  if (note === null)
    return memo.runtime.log({ message: "대상 메모 창을 찾지 못했습니다…" });
  return memo.ui.toast({ title: "지금 메모", message: note.path });
});
```

설정 창은 노트 창이 아니라서 이 경로로 들어온 실행에는 **창 컨텍스트가 없다.** 창-스코프 호출(`ui.toast`·`notes.current`·`editor.*`·`clipboard.*`)은 호스트의 폴백 계약을 탄다 — 마지막으로 쓴 메모 창이 있으면 거기로 가고, 없으면 오류가 아니라 `null`이다. 그때는 토스트도 같은 이유로 못 뜨므로 `memo.runtime.log`가 유일한 창구다 — 그리고 그 줄은 두 곳에서 보인다: 누른 직후 **버튼 아래 상태 줄**(설정 창이 클릭 뒤 최대 2초까지 지켜본다)과 「설정 › 플러그인 › 이 플러그인 › 최근 오류」. 즉 이 메시지는 저작자용 메모가 아니라 **사용자가 그 자리에서 읽는 문장**이다.

그래서 **설정 버튼에는 창이 필요 없는 동작이 가장 잘 맞는다**: 캐시 비우기, 값 다시 계산, 외부 상태 초기화.

### 3. `when`·`destructive` 대신 `confirm`

| 무엇                   | 어디서 판정·표시          | 설정 버튼에서                      |
| ---------------------- | ------------------------- | ---------------------------------- |
| `when`                 | 메모 창의 상태            | 실행 거부 + 진단(판정할 창이 없음) |
| `destructive`          | 메모 창의 확인 팝업       | 실행 거부 + 진단(띄울 창이 없음)   |
| `confirm` (매니페스트) | **설정 창이 직접 띄운다** | 이것을 쓴다                        |

되돌릴 수 없는 동작이면 명령 쪽 `destructive`가 아니라 설정 필드의 `confirm`으로 확인을 받아라.

### 4. 설정 창은 완료를 기다리지 않는다

버튼을 누르면 설정 화면은 "실행을 요청했어요"까지만 말하고 폼은 계속 살아 있다. 명령은 중앙 호스트의 샌드박스에서 비동기로 돌고, 설정 폼이 그 실행에 매달리는 일은 없다 — 느린 플러그인이 설정 창을 인질로 잡을 수 없다는 뜻이다. 대신 **결과를 사용자에게 알리는 책임은 플러그인에게 있다**(토스트 또는 진단).
